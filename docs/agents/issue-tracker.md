# 问题跟踪器：本地 Markdown

本仓库的问题和规格说明以 Markdown 文件形式存放在 `.scratch/` 中。

## 约定

- 每个功能使用一个目录：`.scratch/<功能标识>/`
- 规格说明文件为 `.scratch/<功能标识>/spec.md`
- 每个实现任务使用独立文件，路径为 `.scratch/<功能标识>/issues/<编号>-<任务标识>.md`
- 编号从 `01` 开始，不得将所有任务合并到一个文件中
- 分类状态记录在任务文件顶部附近的 `Status:` 行中，状态值参见 `triage-labels.md`
- 认领后增加 `Owner:`，填写 GitHub 用户名或团队内唯一标识
- 评论和讨论记录追加到文件底部的 `## Comments` 标题下

## 当技能要求“发布到问题跟踪器”时

在 `.scratch/<功能标识>/` 下创建新文件；如果目录不存在，则先创建目录。

## 当技能要求“获取相关任务”时

读取指定路径的文件。用户通常会直接提供文件路径或任务编号。

## 路径探索操作

供 `/wayfinder` 使用。每项工作使用一个**地图文件**，并为每个任务建立一个**子任务文件**。

- **地图**：`.scratch/<工作标识>/map.md`，包含备注、已有决策和待澄清事项
- **子任务**：`.scratch/<工作标识>/issues/<编号>-<任务标识>.md`，编号从 `01` 开始，正文中记录待解决的问题
- `Type:` 行记录任务类型：`research`、`prototype`、`grilling` 或 `task`
- `Status:` 行记录任务状态：`claimed` 或 `resolved`
- **依赖阻塞**：在文件顶部附近使用 `Blocked by: 编号, 编号`；列出的所有任务均为 `resolved` 后，当前任务才解除阻塞
- **可执行任务**：扫描 `.scratch/<工作标识>/issues/`，寻找尚未解决、未被阻塞且无人认领的任务；编号最小者优先
- **认领**：开始工作前，将状态设置为 `Status: claimed` 并保存
- **解决**：在 `## Answer` 标题下追加答案，将状态设置为 `Status: resolved`，然后在 `map.md` 的已有决策部分追加上下文摘要和链接
