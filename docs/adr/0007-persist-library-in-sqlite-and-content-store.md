# ADR-0007：SQLite 作为资料库事实源，全文使用内容寻址文件存储

- 状态：已接受
- 日期：2026-10-22

## 背景

AutoResearch 需要在 Agent 进程重启后保留成果、证据、审核决定和可搜索索引。研究正文可能较大，也可能受访问策略限制；把它们全部放进 Git 或内存会混淆公开代码与实验数据的边界。

## 决策

PoC 使用 SQLite 保存业务状态、不可变工件、证据关系、审核追加记录、幂等键、规范化分块和 FTS5 索引。`persist` 正文同时写入内容寻址的本地文件目录，文件通过临时文件、`fsync` 和原子替换提交；文件目录是全文备份与 GC 的事实边界，SQLite 中的分块只服务于证据定位和小范围读取。`controlled` 与 `metadata_only` 不保存正文和分块。

来源删除采用 tombstone：保留来源版本与历史工件的审计关系，删除正文、分块和来源索引，并把直接引用及其派生工件标记为 `stale`。正文文件进入 GC 队列，只有确认没有其他未删除来源引用同一哈希时才物理删除。

所有工件提交使用 `BEGIN IMMEDIATE`，在同一事务中完成证据存在性检查、版本分配、工件关系、幂等键和 FTS 索引写入；审核决定只追加，不更新旧行。

## 后果

- SQLite Adapter 可以被 PostgreSQL/对象存储实现替换，领域模型不依赖具体数据库。
- 本地资料目录必须纳入备份与权限管理，且不提交 Git；FTS 索引可由数据库重建。
- SQLite WAL 和短事务适合实验室内部单机/低并发 PoC；高并发部署需要后续 Adapter 迁移。
